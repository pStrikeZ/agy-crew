# agy-crew 0.9.6 — interactive start, help and refresh progress

Runs, account selection and quota handling behave as in 0.9.5. This release adds a way to use a pool account by hand, a readable help text, a `version` command, and progress output for `accounts quota --refresh`.

## Changes since 0.9.5

**`start`.** `agy-crew start <name> [-- <agy args>...]` runs agy interactively in the current terminal and directory as pool account `<name>`, with that account's private HOME, so there is no separate agy login to manage. Arguments after `--` reach agy unchanged, and the command exits with agy's exit code. While agy runs the account is held as by `accounts hold acquire`: `auto` never picks it, it never lends, and its token is never swapped by a loan. The hold ends when agy exits. `start` is refused before launch for an unknown, disabled, signed-out or busy account; a cooldown is only noted on stderr. Without a name it lists the accounts with their state and an example. See [Interactive sessions](../REFERENCE.md#interactive-sessions).

**Help and version.** `agy-crew` with no arguments now prints a grouped overview of every command instead of a one-paragraph usage error; `help` (`--help`, `-h`) prints the same on stdout and exits 0. `version` (`--version`, `-v`) prints the versions of agy-crew and agy.

**Quota refresh progress.** `accounts quota --refresh` used to print nothing until every account was done, and renewing an expired token through agy takes several seconds per account. It now reports on stderr: one `✓`/`✗` line with the time taken per account and, on a terminal, a live line with the account, what it is waiting on and for how long. stdout still carries only the table or JSON, and `--json` off a terminal prints no progress. Accounts are still refreshed one at a time.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. No migration is needed.
