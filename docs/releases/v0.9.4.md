# agy-crew 0.9.4 — account rotation on upstream 503

The account pool, quota handling and the other commands behave as in 0.9.3. This release fixes what happens when the model has no capacity, and makes `auto` rotate between accounts.

## Changes since 0.9.3

**An upstream 503 now rotates accounts.** `UNAVAILABLE (code 503): No capacity available for model ...` matched no failure class, so the run ended at once with no cooldown and no failover, and the next run picked the same account again. It is now its own reason, `upstream_unavailable`:

- The account is parked for that model family for 3 minutes, so the next selection, in the same run or a separate one, uses another account. The short cooldown never shortens a quota cooldown that is still running.
- A new task that changed nothing (`ask` always; other modes when `git status` shows nothing new) is rerun from its original prompt as a new conversation on another account. It is a rewrite, not a continuation. If the workspace was already changed, the run continues the conversation on a borrowed credential, as for quota. An explicit `--account` is never moved. At most two extra attempts are made, because agy already retries a 503 for about two minutes itself.
- When every account is cooling only because of 503s the error says `upstream_unavailable`, not `quota_exhausted`. A background job stops in `attention` (or `error` without a conversation) with `retry_at`.

**`auto` rotates between similar accounts.** Ranking compared remaining quota exactly, so the fullest account won every time even right after it was used. Known quota is now compared in 5% steps, and accounts within a step rotate by least recent use. An account that is clearly fuller still wins.

**Skills.** The jobs skill and its troubleshooting reference tell the orchestrator: on `upstream_unavailable`, if agy had not done anything yet, rewrite the task and start a new run (`restart <job id>` or a fresh dispatch), and do not use `continue`, because a continuation stays bound to the same account and conversation and has nothing to continue from. Use `continue` only after agy changed the workspace, and only after inspecting it.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. No migration is needed.
