# agy-crew 0.9.12 — account rename, tab completion, skills in the shared home, inspect across worktrees

Background runs, account selection and cooldowns behave as in 0.9.11.

## What's new

**`accounts rename <old> <new>` and `accounts refresh-email`.**
- `rename` moves the account's directory, cooldowns, quota snapshot and conversation bindings to the new name. It refuses while the account is in a lease or loan, lends the shared session, or the new name is taken or invalid.
- `refresh-email [<name>...] [--json]` re-reads each account's email from its token file (offline; run `accounts quota --refresh` first to have agy renew the token) and updates the pool record. A missing token, a token without an email, or an email another account already carries is reported and the record is left alone.

**Tab completion.** `agy-crew completion bash|zsh|fish` prints a completion script. It completes commands, subcommands, flags, flag values (models, efforts, `--hosts`, `--family`), account names and job ids. `agy-crew install` sets it up for you (below).

**`install` puts the skills into the shared home.** The shared home (`~/.agy-crew/shared/home`) is the HOME that `start` and pooled runs give agy, so agy now finds the `agy-crew-*` skills there too. It is a new host, `shared` (`~/.agy-crew/shared/home/.agents/skills`), included in every default install without detection; `--hosts shared` selects it alone and `uninstall` removes it with the rest.

**`install` sets up shell completion.** The scripts go to `~/.agy-crew/completions/`. bash and zsh get one marked block in their rc file (`# >>> agy-crew completion >>>` … `# <<< agy-crew completion <<<`) that sources the script; the rest of the file is never touched and a repeat install replaces the block. fish gets `~/.config/fish/completions/agy-crew.fish`; a file you wrote yourself there is left alone and reported as a conflict. A shell is set up when its rc file exists or it is your login shell. `--no-completion` skips it, `--dry-run` writes nothing, and an rc file that cannot be written only warns. `uninstall` removes the blocks and files together with the last skill link.

## Fixes

- **`inspect` now sees jobs started in other worktrees.** Each git worktree keeps its own `.agy-crew/`, so an agent working in an auto-created worktree left its jobs where `inspect` in the main checkout could not see them. `inspect` now merges the jobs of every worktree of the repository (read-only): the Jobs page and status line mark jobs from another worktree with `[worktree-name]`, a bare `inspect` picks the newest job of any worktree, and `inspect <id>` finds it wherever it ran. `--here` restricts the view to the current worktree. A corrupt `state.json` in one worktree is skipped with a warning. `status`, `wait` and `result` still look at the current worktree only.

## Behaviour change

A default `install` now also writes to the shared home and to your shell's rc file (bash, zsh) or fish completions directory. Use `--no-completion` to skip the latter. If you ran an earlier version, remove nothing: the next `install` adds both.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Open a new shell for tab completion and restart the harness for the skills. No migration is needed.

agy's skill directory for the shared home follows its `.agents/skills` convention; check with `/skills` inside `agy-crew start`.
