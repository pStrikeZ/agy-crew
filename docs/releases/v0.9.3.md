# agy-crew 0.9.3 — readable account tables

The pool, selection and quota handling behave as in 0.9.2. This release changes how `accounts list` and `accounts quota` print, and fixes a test isolation bug.

## Changes since 0.9.2

**Aligned account tables.** `accounts list` prints an ACCOUNT table (email, state, last use as a relative time) and a QUOTA table with one row per account and quota pool. Each 5-hour and weekly window shows the remaining percentage, right-aligned, and when it resets: `resets in 4h12m (15:23)`, with the date added when the reset is not today. AS OF shows how old the snapshot is, so stale numbers are visible; a reset that has already passed reads `reset since refresh`. Cooldowns move to their own COOLDOWNS table, and the STATE column reads `cooling`. `accounts quota` prints the same QUOTA table. `--json` output is unchanged.

**Tests never touch the real pool.** Three test spawns ran the companion with the developer's real home directory, so a local test run could update the real pool's `last_used_at` (always with the fake agy; no real agy call or network request). Those spawns now use the sandbox home, and the shared test helper points `AGY_CREW_HOME` at a throwaway directory for the whole test process, so a future test that forgets to isolate itself cannot reach the real pool either.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. No migration is needed.
