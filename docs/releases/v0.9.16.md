# agy-crew 0.9.16 — cooldowns per quota pool

Background runs, `start`, `omp` and the permission model behave as in 0.9.15. This release changes how quota cooldowns are keyed.

## Changes

- **Cooldowns are kept per account and quota pool, not per model family.** Cloud Code bills two pools: every Gemini model draws on `gemini`, everything else on `other`. A cooldown recorded after `gemini-3.8-flash` ran dry now also holds for `gemini-4-carbon` and every other Gemini model on that account, instead of letting each family fail once before it learns. The other pool stays usable. `pool.json` keys are now `<name>|gemini` and `<name>|other`.
- **`--family <f>` still accepts any family.** `accounts cooldown record`, `accounts cooldown clear` and `accounts hold acquire` map the family you give to its pool, so existing callers keep working and may also pass `gemini` or `other` directly.
- **Cooldowns recorded by older versions move to their pool.** The first pool update after upgrading rewrites per-family keys to pool keys; families of one pool merge into the cooldown that ends last. Nothing to do by hand.
- **`accounts list` shows the pool.** The `COOLDOWNS` section and `--json` `cooldowns[].family` now carry the pool name.
- **Test fixtures never ask for a signature.** Fixture repositories set `commit.gpgsign=false`, so running the tests no longer asks a signing key (for example a hardware key) for a touch.

## Upgrading

```bash
npm install -g agy-crew@latest
```

No other step. A tool that records cooldowns for the shared pool, such as Switchblade, should be updated together with it so both sides use the same keys; an older one keeps working, but its cooldowns are then written under a family name that maps to the same pool.
