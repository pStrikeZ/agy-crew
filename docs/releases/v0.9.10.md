# agy-crew 0.9.10 — a shared home for `start`

Background runs, account selection and cooldowns behave as in 0.9.9. This release changes `agy-crew start` for people who use agy by hand, and fixes one quota bug.

## What's new

**`start` without an account name runs in a shared home.** Every pool account keeps its conversations in its own HOME, so a conversation started under one account could not be resumed under another. `agy-crew start` now runs agy in `~/.agy-crew/shared/home`, a HOME that belongs to no account, so `/resume` and `agy --continue` find its conversations whichever account lends the credential.

- On start, an idle account with quota for the model family lends its credential and its Cloud Code project id: it must be enabled and signed in, with no lease, loan or hold, and no cooldown or empty quota snapshot for that family. The fullest account goes first, then the least recently used. When agy exits, the credential, which agy may have refreshed, goes back to the account. If the companion is killed, it goes back on the next pool update.
- `--model <id>` chooses the family the lender needs quota for and is passed on to agy. Without it, the family of the default model (`gemini-3.8-flash`) is used.
- A second `start` while a shared session runs joins it on the same credential; the credential goes back when the last one exits.
- When no account can lend, `start` is refused before launching agy and lists each account's state.
- The lender is held for the session (shown as `shared` in `accounts list`), so background runs stay off it.
- A quota error inside an interactive session is not recorded as a cooldown. Run `accounts quota --refresh` before starting again if the next pick might choose the same account.

`start <name>` still runs as that account in its own HOME, and now accepts `--model` too.

**Behaviour change:** a bare `start` used to print its usage and exit 1. It now starts the shared session; use `start --help` for the usage and the account list.

## Fixes

- `accounts quota --refresh` no longer stores the lender's quota under a borrower's name. While an account's credential is on loan to a running job, its token file holds the lender's credential, so the refresh now skips that account and keeps its last snapshot.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. No migration is needed.
