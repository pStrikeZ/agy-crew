# agy-crew 0.9.18 — quota is read through `agy /usage`

Background runs, the permission model and account selection behave as in 0.9.17.

## Changes

- **`accounts quota --refresh` asks agy instead of Cloud Code.** For each account, one at a time, it runs `agy -p /usage --output-format json` with the account's own HOME and parses the groups and buckets agy prints. The pool no longer calls `loadCodeAssist` / `retrieveUserQuotaSummary` itself, sends no hand-built User-Agent, and no longer warms up an expiring token first: agy renews it while answering.
- **A report is trusted only when agy used file-backed token storage.** Otherwise agy may have read the OS keyring shared by every HOME and reported another account's quota, so the refresh records an error instead.
- **A signed-out account is marked `needs login`** when agy asks for authentication; the 20 s timeout ends the wait for a browser login.
- **The plan type is no longer recorded** (`/usage` does not report it), and `AGY_CREW_CLOUDCODE_URL` no longer has any effect. Progress now reads `asking agy /usage`.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. Run `agy-crew accounts quota --refresh` once to replace the cached snapshots.
