# agy-crew 0.9.17 — choose the HOME `start` runs in

Background runs, the permission model and account selection behave as in 0.9.16.

## Changes

- **`start` can run agy in your real HOME.** By default agy still runs in the shared home (`~/.agy-crew/shared/home`), which plugins and hooks installed in your own `~/.gemini` (third-party plugins that install themselves there) cannot see. `agy-crew accounts start-home real` makes your real HOME the default; `start --real-home` / `--shared-home` override it for one session, and `accounts start-home` without an argument prints the current choice. Unset means `shared`, so nothing changes unless you opt in.
- **The real HOME's own login is protected.** The pool credential and project id are put into `~/.gemini/antigravity-cli`; whatever token or project id was there is moved aside (`*.agy-crew.shared-backup`) and restored when the last session exits, or on the next locked pool update if agy-crew was killed. A leftover backup refuses the start instead of being overwritten. `settings.json` is not touched, and the live permissions are not copied. A `start` that joins a running session uses that session's HOME.
- Shell completion, `help`, `start --help` and the `agy-crew-accounts` skill know the new setting.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. To use the real HOME by default: `agy-crew accounts start-home real`. Conversations started there live in the real HOME, not in the pool, as with the shared home.
