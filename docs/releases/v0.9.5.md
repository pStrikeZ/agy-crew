# agy-crew 0.9.5 — external holds

Runs, account selection and quota handling behave as in 0.9.4. This release adds a way for another program that uses a pool account's credential to keep agy-crew off that account while it does, and to report quota resets it learns.

## Changes since 0.9.4

**`accounts hold`.** `accounts hold acquire <name> --pid <pid> [--family <f>] [--json]` holds an account for the process `<pid>`; `accounts hold release <id>` ends the hold, and it also ends when that process exits. While an account is held:

- `auto` never picks it and it never lends its credential;
- an explicit `--account <name>` for it fails before launch;
- a conversation bound to it continues on a borrowed credential, as when its account is cooling;
- `list` shows it as `held`, and `remove` and `login` refuse it.

A hold is refused when agy-crew has no such account (`unknown`), when the account has another lease or loan (`busy`), or, with `--family`, when that family is cooling or its quota snapshot is empty (with `retry_at`). With `--json` a refusal prints `{ "refused": ... }` and exits 1. See [External holds](../REFERENCE.md#external-holds).

**`accounts cooldown record`.** `accounts cooldown record <name> --family <f> --retry-at <time>` records a quota cooldown learned outside agy-crew. It never shortens a cooldown already in force.

## Upgrading

```bash
npm install -g agy-crew@latest
agy-crew install
```

Restart the harness. No migration is needed.
