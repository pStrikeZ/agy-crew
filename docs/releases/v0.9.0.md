# agy-crew 0.9.0 — account pool

0.8.0 forked agy-staff and added the installer. 0.9.0 adds the feature the fork was made for: an **account pool** that runs concurrent agy jobs on different accounts, with quota tracked per account and per model family.

## Changes since 0.8.0

**Pool accounts and the live login.** A pool account is a named, private HOME under `~/.agy-crew/accounts/<name>/home/` with its own file-backed agy token. Your own agy login (**live**) is never pooled: `auto` never picks it, it never lends a credential and never borrows one. It is used only with `--account live`, or when the pool has no enabled account, so with an empty pool every behaviour is exactly as in 0.8.0.

**`accounts` command.** `accounts list|quota|login|import|enable|disable|cooldown clear|remove`, with `--json` output.

- `accounts login <name>` is interactive (browser sign-in) and must be run by the user in their own terminal; agents must not run it.
- `accounts import <name> --home <dir>` copies the token from an existing HOME-shaped directory, such as an agy-cli-manager account directory.
- `accounts remove <name>` only previews the deletion until `--yes` is given.
- `accounts quota --refresh` queries Google's Cloud Code service and is the only place the pool uses the network. `AGY_CREW_CLOUDCODE_URL` overrides the endpoint.

**`--account auto|live|<name>`** on `ask`, `staffer`, `research`, `review`, `implement`, `continue` and `restart`; default from `AGY_CREW_ACCOUNT`, else `auto`. `auto` prefers an idle account, then the most remaining quota, then the least recently used. The account is shown in the telemetry line, `status`, `result` and `observe`. Conversations stay bound to the account that created them; continuing one with a conflicting explicit account is refused.

**Quota awareness.** A quota failure records a cooldown keyed by account and model family, with the reset time parsed from agy's `Resets in` text (60 minutes when it cannot be parsed). A run that had not started a conversation fails over to another account. A run inside a conversation borrows an idle account's credential (a **credential loan**) and continues; the token files are restored afterwards and by crash recovery. If nothing can continue, the job ends with reason `quota_exhausted` and a `retry_at` (status `attention` and exit 5 when a conversation exists, otherwise `error`). Authentication failures mark the account `needs login` and are never retried.

**`setup --apply`** now also applies its permission merge to every pool account's `settings.json` and reports each path.

**Skills.** New `accounts` skill. `jobs` explains how to read `quota_exhausted`, `retry_at` and `needs login`; `lead` sizes parallel work to the number of ready accounts. The persona skills list `--account`. OpenCode now registers eight skills, including `/agy-crew-accounts`.

**Docs.** New Account pool sections in the README, the reference (flags, state layout, selection ranking, loans, failure reasons), the agent install guide and the design document, in English and Chinese. A broken anchor in the Chinese reference was fixed.

**Unchanged.** Personas, background jobs, the permission profiles and every companion command other than `accounts` behave as in 0.8.0.

## Upgrading

```bash
npm install -g github:pStrikeZ/agy-crew
agy-crew install
```

Restart the harness. No migration is needed: with no pool accounts, behaviour is unchanged. To start using the pool, run `agy-crew accounts login work1` in your terminal, then `agy-crew accounts list`. See [Accounts](../REFERENCE.md#accounts).
